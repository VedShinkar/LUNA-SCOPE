# Phase 4 API integration audit

The starting branch is `feature/horizons-validation-pilot`. Several scientific, terrain, validation and frontend files are modified or untracked. The worktree already includes the graphite Site Analysis shell and shared observer navigation. The mounted FastAPI routes cover terrain, celestial, solar, Earth visibility and the operational timeline.

| Service | Python entry points and inputs | Result and dependencies | HTTP at audit |
| --- | --- | --- | --- |
| Mission Intelligence | `app.mission.decision_engine.engine.assess_site` accepts a mission-domain site identifier, optional UTC range, increment, four weights, slope and roughness thresholds, and antenna mask. Weights must sum to one. | `SiteAssessment` with four criteria, weighted preliminary score, missing criteria, preliminary label and provenance-bearing terrain, solar and Earth measurements. Partial scores re-normalize available weights. There is no definitive feasibility flag. | None |
| Site comparison | `engine.compare_sites` applies the same engine and inputs across a list of mission sites. | Mapping of site identifiers to assessments in input order. It does not rank or validate the comparability of partial scores. | None |
| Copilot | `app.ai_copilot.copilot` exposes `site_assessment_response`, `multi_site_comparison_response`, `terrain_query_response`, `illumination_query_response` and `communication_query_response`. | Structured `CopilotResponse` with evidence, statuses, limitations and missing inputs. No general prompt parser, LLM, conversation store or external actions exist. | None |
| Mission profiles | `app.models.mission_timeline.MissionProfile` v1 defines Sun requirement, Earth criterion, optional full-disc preference, antenna mask and continuous duration. | Validated by the timeline API and used by the browser's existing local profile storage. The scoring engine has separate thresholds and weights. | `GET/POST /terrain/explorer/mission-timeline/profile` |
| Equipment | The only equipment-related parameter on the production decision engine and Copilot is minimum antenna elevation. | No equipment catalog, hardware profiles, link budgets or power simulator were found. The HTTP contract can represent a named configuration carrying that supported geometric mask. | None |
| Terrain | `decision_engine.adapter.get_terrain` maps each catalog site, calls `TerrainService.query_point` at the native raster centre and catches unavailable or invalid data. | Elevation, slope, roughness, hazards, uncertainty and provenance, or `INSUFFICIENT_DATA`. | Existing terrain point and explorer APIs |
| Solar and Earth | `adapter.get_illumination` and `get_communication` call the existing observer analyses. Their current adapters always supply the centre; Earth accepts a mask and criterion, while the assessment currently uses the centre criterion. | `TemporalMeasurement` with real duration summaries, method, kernels, quality flags and errors. Geometric evidence may be provisional or unresolved. Solar's nominal schedule excludes a nonaligned terminal epoch, whereas Earth includes it. | Existing point, series and region APIs |
| Operations timeline | `app.scientific_engines.mission_service.timelines` accepts native site/point selections, UTC interval, bounded increment and profile. | Shared native observer, five tracks, true UTC boundaries, durations, brackets and provenance. The engine does not accept timeline durations as scoring criteria. | Existing site, compare, inspect and refine APIs |

The integration tests use isolated synthetic fixtures to cover scoring and status propagation. Production adapters read local LOLA data and SPICE geometry. Frontend analysis navigation currently shows three unavailable views and already carries a site and projected observer between workspaces.

## Integration plan

1. Extend existing measurement and scoring entry points with optional point and Earth criterion arguments, keeping existing callers and score formulas. Resolve one native observer for the HTTP request. Derive its elevation from LOLA. Use an identical bounded nominal schedule for score comparisons.
2. Return the operational timeline as separate evidence. Preserve insufficient and unresolved states and the preliminary score label. A UTC instant supports point observations but does not produce temporal duration scores. Compare scenarios only when their scored criteria and sampling support are compatible.
3. Route explicit Copilot actions to the existing structured response helpers. Extend the optional observer context rather than inventing a conversational engine. Fetch evidence on the server using the request context, so browser measurements cannot overwrite scientific inputs.
4. Connect the existing workspaces to typed HTTP contracts. Surface the supplied assumptions and limitations. Test real site and observer identities, profiles, antenna masks and missing data before claiming an integration.
